# F-08 thread 2 — the adapter oracle must route each client through its own adapter

**Date:** 2026-09-03 · **Author:** llm-pm-3 · **Rigor:** c · **Board:** llm-memory-pipeline · **Status:** plan gate

## The defect, as proven

`tools/adapter_oracle.py` is the guard that a stored `conversations/<sid>.md` can be regenerated byte-for-byte. Judge verdict `01788087479282960606-f08-codexdrift-review-opus-16edf6a6` (30 Aug) proved by execution that every codex-prefixed session in the corpus fails the oracle **by construction**, not by drift:

- `regenerate()` hardcodes the Claude adapter and points it at `transcripts/<sid>.jsonl`. For a foreign client that file is this project's own envelope (`adapters/envelope.py`), not the client's transcript, and the regenerated frontmatter says `client: claude` against a stored `client: codex`.
- `compare()` takes the already-migrated branch for any stored file that carries `client:`, so no allowance is ever granted, and the mismatch is reported as content drift.
- Routed correctly — the codex adapter reading the client's own file named by the stored frontmatter `raw_source:` — all 365 codex sessions reproduced byte-for-byte, 365/365.

Three documentation candidates (07ed46e, 08bc4967, the F2 half of 37e9bc9) described a "codex compatibility gap" that does not exist; none merged. `docs/adapters.md` "Known pre-existing drift" still carries the 10-session figure from mid-August and is wrong on every number.

The grok adapter merged today (b3cf2b2) adds 564 more foreign sessions that the oracle currently reports as failures for the same reason.

## Decisions

**D1 — Route by owner.** `regenerate(session_id)` resolves the owning client with `adapters.client_for_session_id(session_id)`. Claude sessions keep the current path (archived transcript through `adapters.claude`). A foreign session is regenerated by its own adapter from the client's own file named in the stored `.md`'s `raw_source:` frontmatter, via that adapter's `ref_for_path` (grok's takes the session directory, so the adapter's mapping from `raw_source` to a ref is the adapter's business; the oracle asks the adapter, it does not guess).

**D2 — Expected client comes from the owner.** `compare()`'s `expected_client` is the owning client's `client_name()`. The `client:` allowance stays exactly as narrow as today and continues to apply only to unmigrated Claude files with no `client:` line; a foreign client's stored file always carries `client:` and is held to plain byte equality.

**D3 — Unavailable is not a mismatch.** A foreign session whose `raw_source` file no longer exists is reported as `unavailable: raw_source missing (<path>)`, counted separately from failures, and does not diff. The same distinct status applies when a stored `.md` has no `raw_source:` at all for a foreign id. Exit code: failures make it 1; unavailable alone does not.

**D4 — Per-client summary.** The final line of every run reports per-client `ok/fail/unavailable` counts alongside the total, so a drift figure can never again silently mix clients. `--all` gains nothing else.

**D5 — Sample unchanged in this arc.** The pinned 20-session sample stays Claude-only; `select()` is untouched. Re-pinning with foreign clients represented is a follow-up decision for the owner (the sample is a contract in CI).

**D6 — Docs from measurement.** After the fix, the implementer runs `--all` fresh and rewrites `docs/adapters.md` "Known pre-existing drift" from the numbers measured that day, per client, keeping the section's method (how to tell drift from regression) and removing the false gap narrative. Numbers are stated as a dated snapshot.

## Frozen tests (separate author; never the live store)

All new tests monkeypatch `CONV_DIR` and `ARCHIVE_DIR` to `tmp_path`, build a stored `.md` by rendering a fixture through its own adapter (so the stored file is byte-true), and then call the oracle's `regenerate` / `check` / `compare`:

1. Trigger, codex: a stored `.md` for `codex-<fixture>` with `raw_source:` pointing at `tests/fixtures/codex/<one>.jsonl` and an envelope in `ARCHIVE_DIR` → `check()` must be OK. Red today: regenerate uses the Claude adapter on the envelope.
2. Trigger, grok: same with a `tests/fixtures/grok/<one>/` directory.
3. Control, claude: an unprefixed session regenerated from `ARCHIVE_DIR` exactly as today, including the single-`client:`-line allowance for an unmigrated stored file.
4. The bug as a test: a Claude-adapter render (`client: claude`) compared against a stored `client: codex` file must FAIL on the client line; that is the current false-drift mechanism, pinned so it cannot return.
5. Unavailable: foreign id whose `raw_source` is absent → status `unavailable`, no diff, exit 0 when it is the only problem; foreign id with no `raw_source:` line → same.
6. Per-client summary: run `main()` (or the summarising function it delegates to) over a tmp corpus of two claude + one codex + one grok session and assert the per-client counts and the exit code.
7. Existing 26 tests in `tests/test_adapter_oracle.py` unchanged; the pinned corpus sample still 20/20 on this machine.
